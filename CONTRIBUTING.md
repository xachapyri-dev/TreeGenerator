# Руководство для контрибьюторов

Спасибо за интерес к развитию проекта **Tree Generator**! Мы приветствуем любые улучшения: исправление ошибок, оптимизацию генерации геометрии, расширение экспортеров и дополнение локализации.

Ниже описаны основные правила и процесс участия в разработке.

---

## 1. Сообщения об ошибках и предложения (Issues)

Перед тем как создать новый Issue:
1. Проверьте вкладку **Closed Issues** — возможно, проблема уже решена или обсуждалась ранее.
2. При сообщении о баге укажите:
   * Операционную систему (Windows 10/11, дистрибутив Linux).
   * Модель видеокарты и версию драйвера (важно для проверки поддержки OpenGL 3.3 Core Profile).
   * Шаги для воспроизведения и текст ошибки из терминала.
   * Если проблема связана с генерацией конкретного дерева — приложите сид (seed) или файл проекта `.tgtree`.

---

## 2. Развертывание среды разработки

Проект использует **Python 3.13**.

1. **Форкните и клонируйте репозиторий:**

   ```bash
   git clone https://github.com/xachapyri-dev/TreeGenerator.git
   cd TreeGenerator
   ```
2. Создайте и активируйте виртуальное окружение:

   Windows:
   
   ```bash
    python -m venv venv
    venv\Scripts\activate
   ```
   Linux:
   
   ```bash
    python3 -m venv venv
    source venv/bin/activate
   ```
3. Установите зависимости для разработки:

  ```bash
   pip install --upgrade pip
   pip install -r requirements-dev.txt
  ```

4. Запустите приложение из исходников:

  ```bash
   python main.py
  ```

## 3. Архитектура проекта

Перед внесением изменений ознакомьтесь с распределением обязанностей в кодовой базе:
  `generator.py` — процедурная генерация дерева (кривые Безье, филлотаксис золотого сечения, расчет сбежистости и нормалей). Код чувствителен к производительности — используйте векторизацию через NumPy вместо медленных циклов Python.

  `gl_widget.py` — вьювер на базе `QOpenGLWidget` и OpenGL 3.3 Core Profile. Рендеринг мешей, шейдерный конвейер и матричные трансформации камеры.

  `export/` — модули экспорта геометрии и материалов:

  * `obj_export.py`, `fbx_export.py`, `glb_export.py` — общие 3D-форматы.

  * `unity_builtin_export.py`, `unity_urp_export.py`, `unity_hdrp_export.py` — генерация YAML-структур для префабов и материалов Unity.

  * `project_manager.py` — сериализация и десериализация архива `.tgtree` (упаковка JSON, геометрии `.npz` и текстур).

`translation/` — файлы локализации интерфейса (`ru.json`, `en.json`).

`UI/` — скомпилированные формы Qt. Если вы редактируете `.ui` файлы через `pyside6-designer`, перекомпилируйте форму командой:

```bash
pyside6-uic QtUI/MainWindow.ui -o UI/MainWindow.py
```

## 4. Требования к коду

Хотя вас никто не заставляет соблюдать требования, это на ваше усмотрение

Одно из главных требований это:
* **Кроссплатформенность:** используйте `os.path.join` или `pathlib` для путей к файлам. Избегайте жестко заданных слэшей (`/` или `\`).

---

## 5. Добавление и обновление локализации

Если вы хотите улучшить перевод или добавить новый язык:

  1. Создайте или обновите соответствующий файл в каталоге `translation/<код_языка>.json`.

  2. Убедитесь, что структура ключей полностью совпадает с оригинальным `ru.json`.

  3. Добавьте новый язык в селектор `UI/LanguageSelect.py` и свяжите с `localization.py`.

---

## 6. Процесс отправки Pull Request (PR)

  1. Создайте отдельную ветку под вашу задачу от актуальной ветки master:
     
  ```bash
     git checkout -b feature/название-фичи
     # или
     git checkout -b fix/описание-бага
  ```

  3. Делайте логичные и понятные коммиты.
     
   * Проверьте работоспособность сборки под Linux (в репозитории настроен GitHub Actions CI, проверяющий билд автоматически при открытии PR).
     
   * Отправьте Pull Request в ветку master основного репозитория с кратким описанием изменений и скриншотами (если затронут UI или визуализация).


Удачи тебе!
